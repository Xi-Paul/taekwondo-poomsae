# 품새 연습장

스마트폰 카메라로 품새를 찍어 관절 각도를 재고, 초등학생이 이해할 수 있는 별점·한 줄 조언으로 바꿔 주는 웹앱입니다.
서버 없이 GitHub Pages로 배포하고, 기록은 GitHub REST API로 데이터 저장소에 JSON으로 쌓습니다.

## 품새 목록

`config/catalog.json`이 기본 품새 목록이다 (기본동작, 태극 1~8장, 유단자 9개, 경기용 새 품새 4개 = 22개). 이 파일은 워크플로의 설정 보호 대상이 아니라 **zip 업로드만으로 갱신**된다.

`config/poomsae.json`의 `poomsae`는 사용자 조정용이다. 같은 `id`가 있으면 그 값이 catalog보다 우선하고(예: 특정 품새의 `metrics`에서 `kick` 빼기), catalog에 없는 `id`는 목록 끝에 추가된다.

## 파일 구조

| 파일 | 역할 | 수정 빈도 |
|---|---|---|
| `config/poomsae.json` | 아이 이름, 별점 기준값, 조언 문구, 품새별 조정 | 자주 (업데이트 지점) |
| `config/catalog.json` | 기본 품새 목록 (zip으로 갱신) | 품새 추가 시 |
| `js/metrics.js` | 지표 계산 (관절각, DTW 비교) | 계산 방식을 바꿀 때만 |
| `js/store.js` | GitHub 저장/불러오기 | 거의 없음 |
| `js/videostore.js` | 리플레이 영상 저장 (기기 안 / APK 네이티브) | 거의 없음 |
| `android/` | APK 껍데기 (WebView + 영상 저장 브리지) | 저장 기능을 바꿀 때만 |
| `index.html` | 화면 | 화면을 바꿀 때만 |

데이터 저장소(따로 만듦)에는 앱이 다음 파일을 자동으로 만듭니다.

- `records/{아이id}.json` — 연습 기록 요약 (원본 영상·관절 좌표는 저장하지 않음)
- `references/{품새id}.json` — 기준 동작 관절각 시퀀스
- `daily/{아이id}.json` — 매일 운동 기록 (`days.{YYYY-MM-DD}.v.{항목id}` = 값, `note` = 메모)

## 배포

1. 앱 저장소(예: `taekwondo-poomsae`)에 이 파일들을 올리고 Settings → Pages에서 배포.
2. 기록용 저장소(예: `taekwondo-data`)를 **비공개**로 하나 더 만든다. 앱 저장소와 분리하면 Pages는 공개여도 아이 기록은 비공개로 유지된다.
3. GitHub → Settings → Developer settings → Fine-grained token: 저장소를 `taekwondo-data` 하나만 선택, Repository permissions → Contents: Read and write.
4. 각 기기에서 앱 → 설정 탭에 사용자 이름/저장소/토큰 입력 → "저장하고 연결 확인". 토큰은 그 기기 브라우저에만 저장된다.

카메라는 HTTPS에서만 열리므로 GitHub Pages 주소로 접속해야 한다 (파일을 직접 열면 동작하지 않음).

## 업데이트 방법

서비스 워커(오프라인 캐시)를 쓰지 않고, 설정 파일은 매번 `no-store`로 다시 읽는다. 그래서 GitHub 웹에서 `config/poomsae.json`을 고쳐 커밋하면 Pages 반영(보통 1분 내외) 후 앱을 새로 고치기만 하면 된다.

- 품새 추가: `poomsae` 배열에 항목 추가 (`id`는 영문, 한번 정하면 바꾸지 않기 — 기록·기준 동작 파일 이름이 됨)
- 별점 기준 조정: `metrics.*.stars3`, `stars2`
- 조언 문구 변경: `metrics.*.msg`
- 기록마다 `cfgVersion`이 함께 저장되므로, 기준값을 바꾼 뒤에는 `version`도 올려 두면 언제부터 기준이 바뀌었는지 기록에서 구분된다.

## 촬영 화면

"카메라 켜고 촬영하기"를 누르면 영상이 화면 전체를 차지하는 촬영 모드로 바뀌고 가로로 고정된다. 버튼(카메라 전환·시작/그만·닫기)은 영상 위에 겹쳐 가로일 때 오른쪽, 세로일 때 아래에 있다. 녹화를 마치면 촬영 모드가 닫히고 결과가 나온다.

- APK: 화면 방향을 가로로 고정하고 시스템 바를 숨긴다 (가장자리를 쓸면 잠깐 보임)
- 브라우저(Android Chrome): 전체 화면으로 전환한 뒤 가로 고정
- iPhone Safari: 웹에서 방향 고정이 지원되지 않아 "휴대폰을 가로로 돌려 주세요" 안내만 표시
- 카메라는 화면이 가로로 돈 다음에 켜서 영상도 가로(1280×720)로 녹화된다

## 영상 파일로 올리기

품새 탭의 "영상 파일로 올리기"로 휴대폰에 있는 영상(도장에서 찍은 영상, 사범님 시범 영상)을 분석한다. 카메라 녹화와 같은 파이프라인을 탄다.

- 위의 모드가 **연습하기**면 아이 기록(점수 + 다시 보기 영상), **기준 동작 저장**이면 사범님 기준(비교 점수용 기준 + 다시 보기의 "사범님 기준")
- 영상을 `capture.sampleHz`(기본 15회/초) 간격으로 이동하며 포즈를 추정 → 1분 영상이면 900장 분석 (기기에 따라 1~2분)
- 기록 날짜는 파일의 수정 시각을 쓴다 (미래 시각이면 지금). 다른 경로로 받은 파일은 받은 날짜가 될 수 있음
- 최대 길이 `upload.maxSec` (설정 파일에 없으면 300초)
- 원본 파일 형식(mp4, mov 등) 그대로 저장. 거울 모드는 기본 꺼짐

## 비교 영상 (모범·다른 사람)

품새 탭 모드 "비교 영상" 또는 기록 탭의 "다른 사람 영상과 비교하기"로 이름을 붙인 영상(사범님·형·친구·선수)을 품새별로 여러 개 저장한다 (카메라 촬영 또는 영상 파일). **별점에는 쓰지 않는다** — 아이 수준에 맞춘 별점 기준이 모범(선수·사범님) 값에 끌려가지 않게 하기 위해서다.

- 저장: GitHub `models/{품새id}.json` (이름, 지표값, 관절각 시퀀스), 영상은 이 기기 `model/{품새id}/`
- 연습 결과의 "모범과 비교": 지표별 `나 / 모범`
  - 낮게 서기: 무릎 굽힘(180° − 무릎각)의 비율 → "모범의 62%"
  - 앞차기 높이: 높이비의 비율
  - 팔 뻗기·허리 펴기: 각도 차이(°)
  - 동작 흐름: DTW로 맞춘 관절각 평균 차이, 가장 다른 시점·관절, 빠르기 비
- 다시 보기: "최근 vs 모범" (결과 화면에서 마지막으로 고른 모범)
- 삭제: 모범 영상 모드의 목록에서 (비교 데이터 + 이 기기 영상)
- 비교가 의미 있으려면 고정 카메라로 같은 품새 전체를 찍은 영상이어야 한다. 중계 영상처럼 컷이 바뀌면 관절 각도가 튀어 비교가 흐트러진다

## 매일 운동 기록

`오늘 운동` 탭에서 날짜별로 운동 항목을 체크하거나 횟수를 넣는다. 항목은 **앱에서 "목록 편집"으로 아이별로 추가·수정·삭제·순서 변경**한다 (`daily-items/{아이id}.json`에 저장). 앱에서 편집한 적이 없는 아이는 `config/poomsae.json`의 `daily.items`를 기본값으로 쓴다.

| 필드 | 뜻 |
|---|---|
| `type` | `check`(했다/안 했다) 또는 `count`(횟수·분 등 숫자) |
| `goal`, `unit`, `step` | 목표값, 단위, +/− 버튼 한 번에 바뀌는 양 |
| `optional: true` | 목표 달성 판정에서 제외 (예: 도장 가는 날만 체크) |

- **목표 달성일(빨간 날)**: `optional`이 아닌 항목이 모두 목표 이상
- **운동한 날(노란 점)**: 항목 하나라도 기록했거나, 그날 품새 탭 연습 기록이 있음
- **연속 일수**: 오늘부터 거꾸로 "운동한 날"이 끊기지 않은 일수. 오늘 아직 기록이 없으면 어제부터 센다
- 저장은 입력 후 1.2초 뒤 자동, 화면을 벗어날 때도 저장. 바뀐 날짜만 덮어쓰므로 두 기기에서 서로 다른 날을 기록해도 지워지지 않는다 (같은 날을 동시에 고치면 나중 저장이 남음)
- 기록할 때마다 그날의 목표를 함께 저장(`g`)하므로, 나중에 목표를 바꾸거나 항목을 지워도 **지난 날의 목표 달성(빨간 날) 판정은 바뀌지 않는다.** 오늘은 현재 목록 기준
- 이름만 바꾸면 내부 id가 그대로라 기록이 이어진다. 삭제한 항목의 지난 값은 파일에 남는다

## 다시 보기 (리플레이)

품새 탭에서 연습하거나 기준 동작을 저장하면 영상과 관절 데이터가 함께 **이 기기에** 저장된다. GitHub에는 올라가지 않는다 (용량·아이 영상 보호).

**저장 위치** (설정 탭 → 영상 저장 위치)

| 방식 | 동작 | 지원 |
|---|---|---|
| 폴더 고르기 | 사용자가 고른 폴더에 `{아이id}/{품새id}/{날짜_시각}_{id}.mp4` + `.pose.json` 파일로 저장. 파일 관리자에서 그대로 보인다 | File System Access API를 지원하는 브라우저(데스크톱 Chrome·Edge 등). Android Chrome은 버전에 따라 폴더 선택이 안 될 수 있음, iOS Safari는 미지원 → 버튼이 자동으로 숨겨짐 |
| 앱 안에 저장 (기본) | 브라우저 저장공간(IndexedDB) | 모든 브라우저 |

- 앱 저장공간은 저장공간이 부족하면 브라우저가 지울 수 있어 `navigator.storage.persist()`로 보존을 요청한다. iPhone은 홈 화면에 추가해서 쓰는 것이 안전하다.
- 오래 보관할 영상은 목록의 **내보내기**로 옮긴다. 휴대폰에서는 공유 창이 열려 사진첩·파일·드라이브로 저장할 수 있고, 공유가 안 되는 환경에서는 다운로드로 받는다.
- 녹화 형식은 mp4를 먼저 시도하고 안 되면 webm. 화질은 `replay.bitrate`(기본 2 Mbps → 1분 약 15MB).

**보는 기능**
- ¼배·½배 느리게, 한 프레임씩 앞뒤(1/sampleHz 초), 뼈대 겹쳐 보기, 거울 모드
- 지금 화면의 무릎·팔꿈치·몸통 각도 표시 — 결과 화면의 지표와 같은 정의
- **처음 vs 최근**, **최근 vs 사범님**, 또는 목록에서 두 개를 골라 나란히 비교. 두 영상은 관절각 흐름을 DTW로 맞춰서, 왼쪽을 재생하면 오른쪽이 같은 동작 위치로 따라간다. 빠르기가 달라도 같은 동작끼리 보이며 각도 차이도 함께 나온다

**한계**: 뼈대는 sampleHz(기본 15회/초)로 기록되어 영상보다 덜 매끄럽다 (`capture.sampleHz`를 30으로 올리면 부드러워지지만 기기 부하 증가). 같은 자세가 오래 이어지는 구간은 비교 위치가 조금 어긋날 수 있다.

## Android APK

`android/`는 GitHub Pages의 웹앱을 그대로 띄우는 WebView 앱이다. 화면·지표·설정은 모두 웹앱 쪽이라 **zip 업로드만으로 갱신되고 APK를 다시 설치할 필요가 없다.** APK는 웹앱이 못 하는 것만 맡는다.

| 기능 | 위치 |
|---|---|
| 영상 저장 | `Movies/품새연습장/{아이id}/{품새id}/…mp4` — 갤러리·파일 관리자에 보임 |
| 관절 데이터 | `Documents/품새연습장/{아이id}/{품새id}/…pose.json` |
| 공유 | 안드로이드 공유 창 (카톡, 드라이브 등) |
| 화면 꺼짐 방지 | 카메라 켜진 동안 |
| 촬영 모드 | 가로 고정, 상태바·내비게이션바 숨김, 뒤로 가기 = 촬영 닫기 |
| 자동 업데이트 | Releases 확인 → 다운로드 → 설치 창 |
| 파일 선택 창 | 영상 파일로 올리기 (WebView는 직접 구현해야 열림) |

- Android 10 이상 (minSdk 29). MediaStore를 쓰므로 저장소 권한 없이 카메라 권한만 요청한다.
- 웹앱은 `window.TkdNative`가 있으면 APK 저장을 쓰고, 없으면(iPhone·PC 브라우저) 기존 방식으로 동작한다.
- 아이 id(`children[].id`)는 영문·숫자·`_`·`-`만 쓸 것 — 폴더 이름이 된다.

**빌드**: 같은 워크플로가 zip을 푼 뒤 `android/`가 바뀌었으면 APK를 빌드해 Release(`apk-1.0.N`)에 첨부한다. 웹 파일만 바뀌면 빌드하지 않는다. Actions 탭 → "압축 풀고 배포" → Run workflow로 수동 빌드도 가능.

**자동 업데이트**
- 웹(화면·지표·기능): APK가 실행할 때마다 `index.html?t=…`로 열고, 웹앱은 JS 모듈을 `?v=…`로 받아 WebView 캐시와 상관없이 항상 최신. zip 업로드 → Pages 배포(1~2분) 후 앱을 다시 열면 반영
- APK: 앱을 열 때(1시간에 한 번) GitHub Releases에서 `apk-1.0.N` 중 가장 큰 N을 찾아 설치된 versionCode(= 빌드 번호)보다 크면 "업데이트할까요?" → APK를 받아 안드로이드 설치 창을 띄운다 (PackageInstaller 세션). 설정 탭 "APK 업데이트 확인"으로 바로 확인 가능
- 처음 한 번 "이 출처 허용"(알 수 없는 앱 설치)을 켜야 한다. 설치 확인 버튼은 안드로이드 정책상 사용자가 눌러야 한다
- 같은 서명 키로 빌드된 APK만 덮어 설치된다 (아래 서명 키 참고)
- GitHub API는 로그인 없이 IP당 시간당 60회 — 기기당 1시간 1회라 충분

**서명 키**: `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD` 두 Secret이 있어야 매 빌드가 같은 키로 서명되어 **덮어 설치**가 된다. 키를 잃어버리면 앱을 지우고 새로 설치해야 하고, 그러면 이전에 저장한 영상이 앱 목록에서 사라진다 (갤러리에는 남음). 키를 직접 만들려면:

```
keytool -genkeypair -keystore release.jks -storetype PKCS12 -alias poomsae -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 release.jks   # 출력 전체를 ANDROID_KEYSTORE_B64에
```

## 한 달 정리

"한 달" 탭은 이미 쌓이는 기록(`daily/`, `records/`)으로 달별 종합을 계산한다 (`js/report.js`, 순수 함수).

- 운동한 날: 운동 항목을 하나라도 기록했거나 품새 연습 기록이 있는 날 / 목표 모두 달성: 그날 저장된 목표 스냅숏(`g`) 기준
- 최장 연속: 그달 안에서 운동한 날이 끊기지 않은 최대 일수
- 운동별: 한 날 수, 합계·하루 평균(기록한 날 기준), 목표 달성일. 목록에서 뺀 항목도 그달 기록이 있으면 표시
- 품새별: 횟수, 평균 점수, 점수와 지표 변화 — 기록이 4회 이상이면 처음 3회 평균 → 마지막 3회 평균, 아니면 첫 기록 → 마지막 기록 (지표의 `better` 방향으로 좋아짐/내려감 판정)
- 지난달 비교: 진행 중인 달은 지난달의 **같은 기간(1일~오늘 날짜)**과 비교
- 요약 복사·공유: 카톡에 붙여 넣을 수 있는 텍스트
- 월말 보관: 끝난 달을 처음 열 때 `reports/{아이}/{YYYY-MM}.json`으로 한 번 저장 (이후 운동 목록을 바꿔도 그달 정리가 남음)

## 지표 정의 (판정 근거)

포즈 인식: MediaPipe Pose Landmarker (관절 33점). 각도는 `worldLandmarks`(골반 중심 3D 좌표, 미터)로 계산해 카메라 거리에 영향을 덜 받게 했고, 발차기 높이만 화면 좌표 비율을 쓴다. 초당 15회 기록, 각 시계열에 5점 이동 중앙값을 적용해 한두 프레임 튀는 값을 제거한다. 어깨·골반·무릎·발목 8점이 모두 신뢰도 0.5 이상인 프레임만 쓴다.

| 지표 | 계산 | 왜 이렇게 |
|---|---|---|
| 낮게 서기 | 발차기 중이 아닌 프레임(발차기 높이비 < 0.15)에서 `min(왼무릎각, 오른무릎각)`의 하위 10% | 앞굽이 순간의 굽힘을 보되, 발차기 때 무릎 접는 동작은 제외. 최솟값 대신 10%를 써서 순간 오인식에 덜 흔들림 |
| 팔 쭉 뻗기 | `max(왼팔꿈치각, 오른팔꿈치각)`의 상위 10% | 지르기·막기 끝에서 팔이 펴진 정도 |
| 앞차기 높이 | `(지지발 발목 y − 차는 발목 y) ÷ (지지발 발목 y − 골반 중심 y)`의 최댓값 | 1.0이면 발목이 골반 높이. 아이 키와 화면 거리에 무관한 비율 |
| 허리 펴기 | 골반중심→어깨중심 벡터와 수직선 사이 각의 상위 10% | 동작 중 상체가 숙여지는 정도 |
| 사범님 동작 따라하기 | 관절각 8개 시퀀스를 DTW로 시간 정렬한 뒤 평균 각도 차 | 빠르기가 달라도 같은 동작끼리 맞춰 비교. 가장 차이 큰 관절과 2초 구간 위치도 함께 알려 줌 |

`config/poomsae.json`의 별점 기준값은 **초기 추정치**다. 실제 아이 기록 몇 번과 사범님 시범을 측정한 값을 보고 조정해야 의미 있는 별점이 된다. 결과 화면에 측정값과 기준값이 함께 표시되므로 그걸 보고 고치면 된다.

## 알려진 한계

- 카메라 1대 = 2D 영상에서 깊이를 추정하므로, 몸이 카메라 쪽으로 향한 동작(정면 지르기 등)의 팔꿈치각 오차가 커진다. 아이 측면 45° 정도에서 찍으면 줄어든다.
- 기준 동작 비교는 **같은 위치·같은 방향에서 찍은 기준 영상**이어야 의미가 있다. 품새 중 방향 전환이 있으므로 기준과 연습의 카메라 위치를 맞출 것.
- 30fps 카메라에서는 빠른 발차기 정점이 흐려질 수 있다. 앱은 60fps를 요청하지만 기기가 지원하지 않으면 낮아진다.
- 동작 순서가 틀렸는지(예: 막기 대신 지르기)는 직접 판정하지 않는다. 순서가 다르면 DTW 차이 값이 커지는 것으로만 드러난다.
